# ADR 001: 升级为自驱动 AI 项目

**日期**: 2026-02-02
**状态**: 已接受

## 背景

qcc_plus 项目已经具备了良好的基础结构（.claude/skills/, CLAUDE.md, 完善的文档），但缺少项目记忆系统和自动化能力。为了提升开发效率、防止重复造轮子、建立知识库，决定升级为自驱动的 AI 项目。

## 决策

添加以下内容：

### 1. 项目记忆系统（.claude-memory/）
- `context.json` - 项目上下文和模块信息
- `environment.json` - 环境配置和命令
- `errors.json` - 错误记录和解决方案
- `iterations.md` - 迭代历史
- `lessons-learned.md` - 经验教训
- `decisions/` - 架构决策记录（ADR）

### 2. 自动化能力（.claude/）
- `hooks/settings.json` - Git hooks 配置
- `agents/` - 专用代理（test-agent, doc-agent）
- `scripts/` - 辅助脚本（搜索、更新、维护）
- `config.json` - Claude 配置文件

### 3. 文档系统增强
- `docs/modules/REGISTRY.md` - 模块注册表（防止重复造轮子）
- `docs/api/INDEX.md` - API 索引
- `TODO.md` - 任务列表

### 4. 测试覆盖率配置
- 目标：100% 覆盖率
- 当前：18.5% 覆盖率
- 需要补充测试

## 保留内容

- 所有现有代码
- 现有测试（6个测试文件）
- 现有文档（30+ 文档）
- 现有 .claude/skills/（6个技能）
- 现有配置（.env, docker-compose.yml 等）
- Git 历史

## 影响

### 正面影响
1. **防止重复造轮子**：模块注册表记录所有现有功能
2. **知识积累**：错误和解决方案自动记录
3. **自动化开发**：可以通过"开始"启动 AI 驱动的开发
4. **提升测试覆盖率**：明确目标 100%
5. **文档同步**：自动更新文档和注册表

### 潜在风险
1. **学习成本**：团队需要了解新的工作流程
2. **维护成本**：需要保持文档和注册表同步

### 缓解措施
1. 提供清晰的使用文档
2. 自动化脚本减少手动维护
3. 增量采用，不强制使用所有功能

## 替代方案

### 方案 A：保持现状
- 优点：无需改变
- 缺点：继续面临重复造轮子、知识流失问题

### 方案 B：只添加模块注册表
- 优点：改动最小
- 缺点：缺少自动化能力和知识积累

### 方案 C：完全重构（选择）
- 优点：获得完整的自驱动能力
- 缺点：改动较大，但风险可控（只添加新文件）
