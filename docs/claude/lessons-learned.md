## 代码类

### [2025-12-10] 前端页面 CSS 硬编码颜色
- **现象**：新页面在深色主题下显示异常，颜色与系统风格不一致
- **原因**：直接使用硬编码颜色值（如 `#ffffff`、`#333`）而非 CSS 变量
- **解决**：全面清理硬编码颜色，统一使用 CSS 变量（如 `var(--bg)`、`var(--text)`、`var(--border)`）
- **预防**：**开发新页面时，禁止使用硬编码颜色，必须使用 `index.css` 中定义的 CSS 变量**

### [2025-11-30] Codex 执行卡住无响应
- **现象**：`codex exec` 命令运行超过 30 分钟无输出
- **原因**：网络问题或 API 超时
- **解决**：使用 `KillShell` 终止后重试，或设置 timeout
- **预防**：对于简单分析任务，直接用 Claude 而非 Codex

### [模板] Shell 转义问题导致 Codex 失败

### [2026-02-10] 流式请求（SSE）被 retryBufferWriter 无限缓冲导致客户端卡住
- **现象**：用户端在任务进行中直接卡住，无任何输出，重试也无法成功
- **原因**：`retryBufferWriter` 的 `Flush()` 方法在 `flushed=false` 时是 no-op。流式请求的 SSE 数据被 `Write()` 写入内存缓冲，但 `Flush()` 不会将数据发送给客户端。客户端在整个请求完成前看不到任何输出。如果上游卡住，要等 120 秒空闲超时后才重试，重试期间客户端仍然什么都收不到
- **解决**：在 `retryBufferWriter` 中增加流式模式（`streaming` 字段）。流式模式下，当收到成功响应（200）的第一块数据后，`Flush()` 自动触发 `FlushToReal()`，将数据立即透传给客户端。同时在 handler 中从 header/query 和 body 的 `stream` 字段检测流式请求
- **预防**：涉及 `retryBufferWriter` 的改动必须同时考虑流式和非流式两种场景。流式请求的核心要求是"数据到达即透传"，不能被缓冲机制阻断

## 配置类

### [模板] 环境变量未生效
- **现象**：修改 .env 后服务行为未变化
- **原因**：Docker 容器未重启 / 变量名拼写错误
- **解决**：`docker compose down && docker compose up -d`
- **预防**：修改配置后必须重启服务

## 部署类

### [模板] CI/CD 健康检查超时
- **现象**：GitHub Actions 部署失败，健康检查超时
- **原因**：服务启动慢 / 端口未开放 / 防火墙
- **解决**：增加等待时间，检查端口和防火墙
- **预防**：本地先测试 `curl http://localhost:8000/health`
